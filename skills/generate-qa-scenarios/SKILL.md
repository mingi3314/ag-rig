# QA 시나리오 생성

## 설계

- 관련 요구사항·변경·구현을 읽고 사용자 목표 → 업무 규칙 → 구체적 예시를 연결한다. 기대 결과는 요구사항에서 도출하고, 구현에서 추론한 동작과 미정 질문은 구분한다. 불확실한 항목을 분리해도 확정 가능한 케이스는 계속 작성한다.
- 핵심 성공 경로와 중요한 오류를 드러낼 반례·경계를 고른다. 상태 전환·연속 사용·데이터 유지·연동·권한·시간·실패 복구 중 해당 기능과 변경에 의미 있는 위험을 살핀다.
- 사용자·업무 영향과 변경·사용 이력을 근거로 우선순위를 정한다. 직접 영향받는 기존 흐름도 포함하되, 중복 케이스나 모든 조합을 나열하지 않는다.

## 작성

- 시나리오마다 검증할 규칙과 상황·결과가 드러나게 한다. 독립적으로 재현할 수 있는 준비 조건·구체적 입력·관찰 가능한 결과를 적는다. 연속 행동 자체가 요구사항이면 그 흐름의 상태를 유지한다.
- 업무 의도를 중심으로 쓰고, 세부 조작·환경 준비는 주석에 둔다. 같은 절차와 검증에서 데이터만 달라질 때 `Scenario Outline`을 사용한다. 빈값·공백은 `Examples`에서 구분되도록 따옴표나 `공백 3개`처럼 명시한다.
- 기존 표기 규칙이 없으면 영문 Gherkin 키워드와 사용자 언어의 본문을 사용한다.

## 산출물

실제 `.feature` 파일로 저장한다. 지정 경로 → 기존 QA 시나리오 위치 → `qa/<feature-name>.feature` 순으로 선택하고, 파일마다 `Feature` 하나를 둔다.

`Rule`이나 `#` 주석으로 규칙과 케이스를 연결한다. 목표·범위·우선 위험과 이유·추적 가능한 근거·준비 조건, 추론·미정 사항·중요한 제외 범위를 짧게 남긴다. 응답에는 파일 링크와 주요 확인 사항을 안내한다.
